## Word-count policy

The counter and engine use the same locale-neutral `Intl.Segmenter("und", { granularity: "word" })` policy and count only `isWordLike` segments. A display-only Unicode fallback can show a count before capability resolution, but conversion fails closed when `Intl.Segmenter` is unavailable. Contractions such as “can’t” normally count as one word; Unicode segmentation may count a hyphenated compound as multiple word-like segments. The displayed count is therefore the engine’s count on a supported runtime, not a separate approximation.

The 12,000-code-unit ceiling and structural bounds are defensive implementation limits, not additional authoring allowances: input must clear them and the 700-word limit before the browser submits `/api/lattice`. The Worker repeats the checks before provider work.

## Outcome and preservation boundary

Text to Lattice is an independently authored pipeline behind one named remote capability. Its order is:

1. validate Unicode, word, character, passage, and batch limits in the browser before any request;
2. after explicit confirmation, acquire the origin-wide browser Web Lock and send one bodyless visitor-session setup to same-origin `POST /api/lattice`, establishing or preserving the signed quota cookie without quota admission or provider work;
3. under that same lock, send exactly one content request containing `{text, requested_mode, schema_version: 1}` to same-origin `POST /api/lattice`; require the valid signed cookie, returning `428 visitor_session_required` when it is missing or `403 invalid_request` when it is invalid, tampered, or undeclared, before admission or provider work;
4. repeat preflight in the Worker before provider work and segment the complete source losslessly into bounded passages and batches;
5. have the fixed server-side Qwen3-235B-A22B-Instruct-2507 generator atomize meaning, select an evidence-supported register, and draft a material candidate while preserving protected source spans;
6. use the fixed server-side Llama 3.1 8B Instruct verifier and deterministic validators to check coverage, fidelity, accessibility, clarity, domain correctness, register fit, and ornament;
7. re-atomize, repair, and recheck rejected work through the same fixed models within request, call, completion, token, and response budgets;
8. certify required multi-batch consistency against the complete source; and
9. return `translated`, `conformant-for-context`, `review-required`, or `unable-to-attempt`, or terminate with one machine-readable request error.

The public engine accepts arbitrary prose within its published bounds and performs its own atomization. It does not certify text as universally or permanently “perfectly Latticed.” `conformant-for-context` returns the unchanged source only after it clears the selected-context checks. `translated` returns a material candidate that cleared the bounded gates; `review-required` returns a semantically releasable material draft with a bounded lower-priority issue and is not a certification of semantic equivalence. The remote capability does not ask clarification questions; it must make a best-supported classification or fail closed. `unable-to-attempt` returns no result text.

The source is not returned as transformed text when no material candidate clears preservation. hah.dev keeps source and result only in bounded request and browser memory and does not write them to application storage, raw logs, caches, queues, analytics, public HTML, manifests, JSON-LD, Markdown, sitemap, or llms files. Hugging Face, DeepInfra, Nscale, and their infrastructure process submitted content under their own policies. The active remote runtime is not asserted to be byte-for-byte equivalent to the historical MLC/WebGPU artifacts.
