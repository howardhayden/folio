## Word-count policy

The counter and engine use the same locale-neutral `Intl.Segmenter("und", { granularity: "word" })` policy and count only `isWordLike` segments. A display-only Unicode fallback can show a count before capability resolution, but conversion fails closed when `Intl.Segmenter` is unavailable. Contractions such as “can’t” normally count as one word; Unicode segmentation may count a hyphenated compound as multiple word-like segments. The displayed count is therefore the engine’s count on a supported runtime, not a separate approximation.

The 12,000-code-unit ceiling and structural bounds are defensive implementation limits, not additional authoring allowances: input must clear them and the 700-word limit before the browser requests a usage lease.

## Outcome and preservation boundary

Text to Lattice is an independently authored, bounded browser pipeline. Its order is:

1. validate Unicode, word, character, passage, and batch limits before a lease or model load;
2. segment the complete source losslessly into bounded passages and batches;
3. have the local generator atomize meaning and select a register passage by passage;
4. draft a material candidate while preserving protected source spans;
5. use a separate local verifier model and deterministic validators to check coverage, fidelity, accessibility, clarity, domain correctness, register fit, and ornament;
6. re-atomize, repair, and recheck rejected work within fixed completion and context budgets;
7. certify multi-batch consistency against the complete source; and
8. return `translated`, `conformant-for-context`, `review-required`, `needs-clarification`, or `unable-to-attempt`.

The public engine accepts arbitrary prose within its published bounds and performs its own atomization. It does not certify text as universally or permanently “perfectly Latticed.” `conformant-for-context` returns the unchanged source only after it clears the selected-context checks. `translated` returns a material candidate that cleared the bounded gates; `review-required` returns a semantically releasable material draft with a bounded lower-priority issue and is not a certification of semantic equivalence. `needs-clarification` returns one precise question without result text. `unable-to-attempt` returns no result text.

The source is not returned as transformed text when no material candidate clears preservation. Output and findings are transient browser state and are not incorporated into public HTML, manifests, JSON-LD, Markdown, sitemap, or llms files.
